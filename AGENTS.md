- Dashboard pages live under src/routes/_authenticated/ and read data with the browser client; tables allow SELECT only to authenticated users (data is internal).
- Public webhook work is attached to the platform execution context so responses can return immediately without abandoning database writes.
- MCP server lives in src/lib/mcp (tools read via the caller OAuth token so RLS applies); routes are generated by mcpPlugin — never hand-write them.
- General commercial and monthly occupancy goals use reserved seller identifiers in sales_goals, excluded from seller analytics; percentage goals are stored as ratios and edited as percentages to keep individual and global comparisons consistent.
- Commercial discount year-over-year comparisons query the matching prior-year reservation window separately and show no comparison when history is absent, avoiding fabricated changes.
- Data access is enforced per role in RLS via has_any_role(); keep policies aligned with the page ACCESS map in src/lib/roles.ts so hidden tabs also mean unreadable data (incl. MCP).
- Migration journal `when` values must stay increasing: 0018 carries a future timestamp, and Drizzle silently skips any migration whose `when` is lower than the last applied one — bump new entries above it and verify in the database after each migration.
- Occupancy follows the HQ Utilization report: per vehicle segment (`reservation_segments`, one per vehicle in a reservation, only confirmed = HQ open/rental/completed), days = max(1, ceil((hours in period − 5h) / 24)) with HQ times used as-is (no timezone shift); capacity = days each vehicle (`fleet_vehicles`) was in the fleet. Verified against Oct/Nov/Dec 2026; the client falls back to whole reservations + `fleet_stats` while the tables are empty. Keep `src/lib/occupancy.ts` and `src/lib/hq-segments.ts` in sync with that rule.
